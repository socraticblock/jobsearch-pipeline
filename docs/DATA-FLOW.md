## How to read this

- **Module** is the path relative to the project root. The reviewer opens the file and finds the callsite at the import line.
- **Network API** is the fully-qualified import. The reviewer can grep for it in the file to find the actual function call.
- **Direction** is inferred from the API name: `urllib`, `requests`, `telegram`, `smtplib` are outbound; `http.server` is inbound. A human-readable correction is acceptable.
- **Surface** is what data crosses the boundary. The tool extracts the literal URL or method from the source where it can, and falls back to one of these honest labels when it cannot:
  - `stdlib parse only, no network call` -- the import is a parse or error helper, not a fetch.
  - `GET <literal>` / `POST <literal>` -- the call site builds a Request with a literal URL; the host is named in the row.
  - `user-supplied URL` -- the URL is a function argument or a variable; the call site in the source file is the only way to know what host is contacted.
  - `user-supplied URL (custom User-Agent)` -- as above, but the module also sets a User-Agent header, which is a fingerprint the user should be able to see at a glance.
  - `imported; surface depends on call site -- see source` -- the tool does not yet summarise this import class; a reviewer should look.

## Adding a sender

A new module that calls out to a third party must (a) add a row to this map by re-running the tool, and (b) be off by default -- no credentials in the shipped artifact, no enabled path in the default profile. The test `tests/test_dataflow_map.py` enforces (a) and asserts no row contains a TBD placeholder; the W2.1..W2.3 workstreams enforce (b).
